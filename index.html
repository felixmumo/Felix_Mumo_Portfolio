About me

Where I come from, what I'm good at, and the direction I'm taking my career.

I am Felix Musyoka Mumo, an ICT Officer based in Kasarani, Nairobi, with a BSc in Information Technology from South Eastern Kenya University. For seven years I have carried the full ICT stack for institutions and non-profits — Microsoft 365 and Azure tenancies, networks and firewalls, servers and websites, endpoint security, CCTV and access control, backups, vendor contracts, and the users who depend on every part of it working.

That range is deliberate. Running infrastructure taught me how organisations actually behave: where records get entered badly, which processes people quietly work around, and why a report nobody trusts gets ignored. It is the reason I can walk into a messy system and know which questions to ask first.

My focus now is data and AI. The part of this work I keep returning to is what happens after a system is live — the records it accumulates. I analyse that data in Python with pandas and NumPy, model and visualise it, and build dashboards in Power BI that answer the questions management is actually asking. I have done this with M-Pesa transaction records, water billing and consumption data, and virtual campus revenue trends, turning raw logs into reporting that shaped real decisions.

In Power BI I work the whole path, not just the visuals: pinning down the business requirements and KPIs first, shaping the data in Power Query, building a clean data model, writing the DAX measures that carry the business logic, and designing interactive reports with slicers and drill-downs. My most recent build is a Hotel Business Dashboard that takes raw booking data to KPI-level insight.

Underneath the analysis sits the discipline that makes it hold up: systems analysis and requirements gathering, database and ERD design, API integration, UAT, and documentation habits that make an analysis reproducible rather than a one-off spreadsheet somebody loses. I have also spent years teaching — CBET practical courses, staff training on Microsoft 365, cybersecurity and data protection — which is how I learnt to explain a technical finding to somebody who does not want the technical version.

I am looking for work where both halves matter: the infrastructure and the numbers coming out of it. If that is the shape of the problem on your desk, get in touch.

A hotel business generates plenty of raw operational data, but in that form it cannot tell management how the business is performing or where to act. The brief was to turn it into an interactive dashboard built around the KPIs the client actually cares about.

  5. Dashboard visualisationDesigned interactive views with charts, tables, KPI cards and slicers.

The result
An interactive dashboard that turns raw hotel data into KPI-level insight a manager can filter and explore without asking for a new report — and a reusable Power BI workflow I now apply to organisational data.

Python data cleaning — Netflix titles dataset

The problem
The Netflix Movies and TV Shows dataset is a realistic mess: missing directors, cast and country values, dates stored as free text, duration mixing minutes and seasons in one column, and inconsistent categorical labels. None of it is usable for analysis as it arrives.
What I did
Worked through the cleaning in a Kaggle notebook with pandas — profiling the data first, handling nulls deliberately rather than dropping rows blindly, converting dates to proper datetime types, splitting and standardising the duration field, removing duplicates, and normalising the categorical columns before running exploratory analysis on the cleaned result.
The result
A reproducible notebook that takes the raw dataset to an analysis-ready table, with each transformation documented so the steps can be re-run or audited.

Python · pandas · SQL · Power BI

M-Pesa payments analysis & reporting dashboard

The problem
M-Pesa statements arrive as long, flat transaction exports. Reconciling them against invoices was manual, slow and inconsistent, and nobody could see collection trends without rebuilding a spreadsheet each month.
What I did
Built a repeatable pipeline in Python to ingest and clean the transaction exports — normalising dates, stripping duplicates, parsing reference codes and matching payments to accounts. Modelled the cleaned data in SQL, then built a dashboard surfacing collection trends, outstanding balances, payment timing and period-on-period comparisons.
The result
Monthly reconciliation dropped from a manual exercise to a refresh. Finance and management read the same numbers, and arrears became visible early enough to act on rather than at year end.

Safaricom M-Pesa STK Push payment gateway

The problem
Customers were paying to a paybill and then sending screenshots. Every payment needed a human to match it to an invoice, and mistakes were routine.
What I did
Integrated the Safaricom Daraja API so the system triggers an STK Push prompt on the customer's phone at checkout. Built and tested the callback handling in Postman so each confirmed transaction posts against the correct invoice automatically, with failed and timed-out payments handled cleanly rather than left hanging.
The result
Payments reconcile themselves. Customers pay from a prompt instead of copying a till number, and the transaction record that lands in the database is the same one the analytics later run on.
